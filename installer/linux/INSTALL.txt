Run ./DropMorph to test the extracted app, or ./dropmorph-cli help for the command line.

Run ./install.sh to install for the current user. It requires Python 3, creates
an application launcher and ~/.local/bin/dropmorph, and does not require root.
Run ./uninstall.sh to remove this installation and DropMorph-downloaded engines.
Your settings and converted files are kept. If integration cleanup fails, the
installation is kept so you can fix the error and run the uninstaller again.
To update, run the install.sh of a newer package: it replaces the installed app and
keeps your settings and engines. Other files in the way are never overwritten.
install.sh warns about missing system libraries and prints the command that installs
them on Ubuntu/Debian, Fedora, Arch and openSUSE.

DropMorph runs on Ubuntu 22.04 or newer and other distributions with glibc 2.35 or
newer. The .NET runtime is bundled; its native system libraries are still
required. Install the desktop and runtime dependencies with:

Ubuntu 24.04:
sudo apt-get install ca-certificates libc6 libgcc-s1 libgssapi-krb5-2 libicu74 libssl3t64 libstdc++6 tzdata zlib1g libfontconfig1 libfreetype6 libx11-6 libice6 libsm6 libxrandr2 libxkbcommon0 libxi6 libxtst6 libxt6 fonts-noto-cjk python3

Ubuntu 22.04:
sudo apt-get install ca-certificates libc6 libgcc-s1 libgssapi-krb5-2 libicu70 libssl3 libstdc++6 tzdata zlib1g libfontconfig1 libfreetype6 libx11-6 libice6 libsm6 libxrandr2 libxkbcommon0 libxi6 libxtst6 libxt6 fonts-noto-cjk python3

Later Ubuntu releases ship a newer libicu (find its name with apt-cache search
libicu). Other distributions use different package names. The desktop needs an
X11 server (or XWayland), fontconfig, FreeType and the X11 libraries above.
X11 supports the global gesture toolbar; it needs libXtst and libXt (libxtst6,
libxt6). A native Wayland session has additional input restrictions; use the
drop window and file-manager actions, or the experimental setup below.

Wayland gesture (experimental, KDE Plasma 6 only, off by default): DropMorph reads
the mouse and keyboard from /dev/input through libinput, and a KWin script moves
the donut to the cursor because Wayland apps cannot place windows. It needs
libinput, libudev and libwayland-client (libinput10, libudev1 and
libwayland-client0 on Ubuntu). To turn it on:
1. Start DropMorph with DROPMORPH_WAYLAND_GESTURES=1 in its environment, for example
   with the line DROPMORPH_WAYLAND_GESTURES=1 in ~/.config/environment.d/dropmorph.conf
   (takes effect after you sign in again).
2. Add yourself to the input group, then sign out and in. Members of that group
   can read all keyboard and mouse input from any program they run, so enable
   this only if you accept that. You may already be in it for other tools.
     sudo usermod -aG input "$USER"
3. Install the KWin script and enable it, so it loads at every login (you can
   also enable "DropMorph donut at the cursor" in System Settings > Window
   Management > KWin Scripts):
     kpackagetool6 --type=KWin/Script --install "${XDG_DATA_HOME:-$HOME/.local/share}/dropmorph/application/kwin/dropmorph-donut"
     kwriteconfig6 --file kwinrc --group Plugins --key dropmorph-donutEnabled true
     qdbus6 org.kde.KWin /KWin reconfigure
Limits: Wayland cannot say which window is under the cursor, so a Ctrl+drag in
any app opens an invisible donut window. It only shows when files are dragged
onto it, but it rejects drops that are not files, so Ctrl+drag to copy text in an
editor or browser can have its drop swallowed near the start point. If that gets
in the way, change the modifier on the Triggers page, for example to Ctrl+Shift.
The excluded apps list does not apply on Wayland. Without the KWin script the
donut opens in the wrong place.

Packages are built and smoke-tested on Ubuntu 24.04 and started on Ubuntu 22.04
by the automated builds.

rhwp and 7-Zip are bundled. Other engines are installed from DropMorph settings or
discovered in the system. Format support depends on available native engines.
Optional engines can require additional system libraries. In particular, calibre
may require libxcb-cursor0, libxcb-xinerama0 and other Qt/XCB dependencies.
